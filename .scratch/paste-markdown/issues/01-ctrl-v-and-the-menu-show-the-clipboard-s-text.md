# 01: Ctrl+V and the menu show the clipboard's text

**What to build:** The reader presses Ctrl+V, or picks "Paste" in the right-click menu, and the window shows the clipboard's plain text rendered, as Open shows a file (**Paste**). Downlight writes the text to a file of its own in its pasted folder, named by the time of the paste, and gives the window that file: it joins **History**, Back returns to the document before it, and the title bar names it and reveals it. Win+V's clipboard history pastes the same way. A clipboard with no text, a busy clipboard, or text that counts as a **Binary file** shows a **Notice** and leaves the window as it was. The empty window's hint names Paste. Pasted files are not deleted yet; ticket 02 does that.

Spec: [Paste Markdown](../spec.md), [ADR 0006](../../../docs/adr/0006-a-paste-is-a-file-downlight-writes.md)

**Blocked by:** None (can start immediately)

**Status:** built, hand checks left

## Results

Built on 2026-11-24.

- **App.** `app/src/paste.rs` holds the command `paste_clipboard` (a blocking task: the clipboard, then `paste`), the pasted folder (`PastedFolder::in_temp()`, `%TEMP%\Downlight\Pasted\`, created by the first write) and `PasteError`, turned into the Notices. A file is created with `create_new`, so a taken name moves on to ` (2)`, ` (3)` and no paste ever overwrites another, even one another process wrote; a file whose write fails is removed again before the Notice names it. Refused text (empty, whitespace only, binary) is refused before the folder is created. The window is given the file with `Documents::give` to that window, as Open and a drop give one.
- **Clipboard.** `platform::clipboard_text` in `app/src/platform/windows/clipboard.rs`: `OpenClipboard` with no window, tried 10 times 25 ms apart before it answers busy, then `CF_UNICODETEXT` through `GlobalSize` and `GlobalLock`, read up to the first NUL and never past the object's size, as the text comes from another program. Guards close the clipboard and unlock the memory on every way out, a panic included. `platform::local_time` (`GetLocalTime`) names the file. windows-sys gained the features `Win32_System_DataExchange`, `Win32_System_Memory`, `Win32_System_Ole` (for `CF_UNICODETEXT`) and `Win32_System_SystemInformation`; Cargo.lock and the notices are unchanged. Other systems' fallback answers `NotAvailable`, and their `local_time` a fixed time, since no file is named by it there.
- **Page.** The commands table gains `paste` (Ctrl+V, no repeat, in the menu after Open) and `leavesEditableFields`, which leaves a command's shortcut to a focused text `input`, `textarea` or editable element; only Paste sets it, so Ctrl+W still closes the window from the Find box, and Copy as Markdown can set it too. A command that sets it is greyed out in the right-click menu when the right-click was in such a field or one has the focus, as its shortcut is left to the field there. The empty window's hint names Paste.
- **Tests.** `app/src/documents/tests/paste.rs` (8 tests, each with its own pasted folder through `PastedFolder::at` and a fixed `LocalTime`), and in `commands.test.ts`, `find.test.ts` and `view.test.ts`.
- **Noteworthy.** Since the clipboard's text is read up to its first NUL, real pasted text never counts as binary; the rule stays for the text the paste module is given, as the spec asks.
- **Measuring (left for the owner).** With `DOWNLIGHT_TIMING` set, each paste writes `timing <window> paste at=... clipboard=... show=...`: `clipboard` is reading the clipboard, `show` writing the file and giving it to the window. Copy the text of `target/documents/mixed-1mb.md` (`npm run documents`) in an editor, run the release build with the switch and press Ctrl+V in a window 5 times, then take the medians; the paste's render is reported after it as any document's is.
- **Left.** The measurement and the hand checks.
