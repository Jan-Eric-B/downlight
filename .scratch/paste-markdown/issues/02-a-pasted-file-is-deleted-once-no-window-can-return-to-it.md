# 02: A pasted file is deleted once no window can return to it

**What to build:** A pasted document's file is temporary (**Paste**, ADR 0006). It is deleted once no open window shows it, has it on its way, or holds it in its **History**: when its window closes, when going somewhere new after Back drops it from History, when the reader stops it on its way (**Stop**), or when another document replaces it before it arrived. While any window can still return to it, Back and Forward included, it stays. When Downlight starts, the pasted folder is emptied, to clear up after a crash, without delaying **First paint**.

Spec: [Paste Markdown](../spec.md), [ADR 0006](../../../docs/adr/0006-a-paste-is-a-file-downlight-writes.md)

**Blocked by:** 01 (Ctrl+V and the menu show the clipboard's text)

**Status:** built, hand checks left

- [x] The document table decides: whenever it lets go of a document (a window forgotten on closing, forward entries dropped by going somewhere new after Back, a document on its way stopped or replaced, a failed show putting the window back), each pasted file it let go of that no window still shows, has on its way or holds in its History is deleted. Deleting happens off the main thread; each file is checked and deleted under one hold of the table's lock, so a window given it meanwhile keeps it.
- [x] "Pasted" means its path is in the pasted folder, whichever way it was given, so a pasted file opened again by its path (Ctrl+O, a drop) counts as the same file.
- [x] A file already gone is no error. Any other failure to delete is left for the next startup's sweep and shown to nobody, since the reader can't act on it; a comment says so.
- [x] When the process starts (not a second launch that hands over to the running process), the pasted folder is emptied on a background task, after the first window's show has started.
- [x] Documents tests: the file is deleted when its window closes; when going somewhere new after Back drops it; when it is stopped on its way; when a paste or another document replaces it on its way; it stays while its window holds it in History (Back from it, then Forward returns to it); it stays while another window shows it or holds it in History, and goes when the last of them lets go; a file already gone is no error; a document outside the pasted folder is never deleted; the startup sweep empties the folder of files from before the process started, and keeps one written since.
- [ ] Hand checks in the release build: closing a paste's window deletes its file; ending the process from Task Manager leaves its pastes, and the next start sweeps them; first paint from the file manager is no slower with pastes left in the folder.
- [x] `npm run check` passes.

## Results

Built on 2026-11-24.

- **The table decides.** `app/src/documents/pasted_files.rs`. Each change that lets go of documents hands what it dropped to `Documents::let_go` after the table's lock, which drops it there too, so no site can do the one without the other: `forget` (the window's whole record), `arrived` (what the window held while its document was on its way, which holds the forward entries going somewhere new after Back dropped), `forget_forward` (a heading visited after Back), `stop` (the document on its way), `change` once it succeeded (the document on its way that a claim replaced; on failure it is put back on its way, so it is let go only then), `put_back` (the show that failed) and a claim that found its window closed (a paste whose window closed while the clipboard was read). The `HoldsDocuments` trait (on a window's record, what it was, its history and what the table took out of them) lists every document held as a `HeldDocument` with a named `key` and `path`.
- **Off the main thread.** A thread of the documents module's own ("pasted files", started by the first job) takes the jobs in order: it keeps only pasted files (`delete_unheld`, comparing the key's folder with the pasted folder's `document_key`, worked out once per job, so a pasted file opened by another path counts), and for each one takes the table's lock, checks that no window holds it by then and deletes it with `remove_file` before letting go of the lock, ignoring its errors (comment in `delete_unheld`).
- **The folder reaches the table** through `Documents::new` (`PastedFolder::in_temp()` in `main.rs`); `paste` and `paste_clipboard` read it with `Documents::pasted_folder`. The tests' recorder gets a folder no test pastes into (`recorded_with`), or the test's own (`recorded_pasting`).
- **The last window.** Closing the last window ends the process right after its `Destroyed` event, which would kill the thread before it deleted the paste, so `main.rs` waits for the jobs at `RunEvent::Exit` (`finish_deleting_pastes`, at most 2 s). The tests wait with the same call before they look at the folder.
- **The startup sweep.** `setup` calls `Documents::sweep_pastes` right after `open_launch` has started the first window's show; it only queues a job, so first paint waits for nothing. A second launch never gets there: the single-instance plugin hands over and exits while the plugins are initialized in `build`, before `setup` runs (Tauri 2.12.5). The sweep keeps a file a window holds by then (a leftover paste opened from the file manager as Downlight starts), which then goes as any paste does. It deletes only files last modified before the process started (`platform::process_start`, or the moment of the sweep where that is unknown), so a paste another Downlight process writes meanwhile, such as one still ending as this one starts, survives it.
- **Tests.** 14 new in `app/src/documents/tests/paste.rs`: deleted when its window closes, when going somewhere new after Back, when a heading is visited after Back, when stopped, when replaced on its way by a paste and by another document, when its window couldn't change to it, when its window had closed; stays in History (Back, then Forward), and while another window shows it (opened by another path) or holds it in History, going with the last; a file already gone; a document outside the folder; the sweep (its leftovers staged a year old), and a file written since the process started surviving it. Ticket 01's tests now give the documents module their folder.
- **Noteworthy.** The thread checks the table when it runs, not when the job was sent, so a document a window took again meanwhile stays. A window given the file between that check and the delete lost it, since the delete came after the lock; fixed on 2026-11-25: the check and the delete of each file now share one hold of the table's lock, which every claim takes, so the claim waits until the file is gone (and the window shows it as gone) or the file stays. One file per hold, so the main thread, which takes the lock as a window closes, waits for at most one delete in the temporary folder. Test: `a_paste_given_to_a_window_as_its_last_window_closes_is_never_deleted_from_under_it`, which puts the claim just before the delete through a test-only hook, `Documents::before_next_delete`, since no public call reaches that moment. Still open: a new paste taking the name of a file that vanished by other means before its job ran, between writing the file and claiming it.
- **Left.** The hand checks.
