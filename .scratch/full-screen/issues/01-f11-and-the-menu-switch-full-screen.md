# 01: F11 and the menu switch full screen

**What to build:** F11, or "Full screen" in the right-click menu, shows the window **Full screen**: a borderless window covering its monitor and the taskbar, with other windows still able to go over it. F11 or the menu entry again leaves it, and the window returns to how it was, maximized or at its size and place. A Notice says how to leave each time the window goes full screen. Full screen belongs to one window, as **Keep on top** does. The title bar still shows as today; ticket 03 hides it.

Spec: [Full screen](../spec.md)

**Blocked by:** None (can start immediately)

**Status:** built, hand checks left

## Comments

**2026-11-20.** Stub from the v1 spec's Out of Scope list (v1.x), so the idea has a ticket. Not yet grilled.

**2026-11-20, from the repo owner.** Grilled and specced: `../spec.md` (ready-for-agent). Full screen only, no zen mode; borderless, so other windows still go over it; F11, a menu entry (no button), and Esc last after the settings flyout, Find and Stop; one window's state, never saved; the title bar hidden and sliding in at the top edge, its maximize button reading "Leave full screen". The stub became this ticket and tickets 02 to 05.

**2026-11-20, built; the hand check is left.** What was built, and what it decided:

- **Window state in the app, as Keep on top's.** The new command `switch_full_screen` (`app/src/full_screen.rs`) takes nothing, flips Tauri's `set_fullscreen` on the calling window by `is_fullscreen`, and answers whether the window is full screen now (`ShownFullScreen`, a `bool`). A failed switch rejects with "Full screen didn't switch: ...", shown as a Notice. tauri-runtime-wry 2.12.3 turns `set_fullscreen(true)` into tao's `Fullscreen::Borderless(None)`, the window's current monitor, never an exclusive one, so there is no choice of kind and no code in the per-OS module. No capability changed: the command is the app's own.
- **A maximized window comes back maximized, by tao, with no memory of Downlight's own.** Read in tao 0.37.2's Windows source (`platform_impl/windows/window.rs`, `set_fullscreen`, and `window_state.rs`): going full screen, tao first changes the window's style with its `MAXIMIZED` flag kept (so the window stays `WS_MAXIMIZE`, and its `WM_SIZE` keeps reporting `SIZE_MAXIMIZED`), then saves `GetWindowPlacement`, whose `showCmd` is then `SW_SHOWMAXIMIZED` and whose `rcNormalPosition` is the windowed size and place, then sizes the window to the monitor. Leaving, it puts the saved placement back with `SetWindowPlacement`, which restores a maximized window maximized over its earlier windowed place, and any other window at its size and place. So the ticket's fallback (remember and maximize again) isn't built; the hand check confirms it. A consequence for ticket 05: tao's `is_maximized` stays true while a maximized window is full screen, so the title bar's `window-state` message says maximized then, and the page must ask full screen first.
- **No place for a full-screen window.** `place_of` in `app/src/window.rs` answers None for a full-screen window too (`is_fullscreen`), beside minimized and maximized, so a closing full-screen window keeps the last windowed size and a new window opened beside one is placed as beside a maximized one. The `Windows` trait's doc (`app/src/documents/show.rs`) says so.
- **The page** has `page/src/full-screen.ts`, shaped like `keep-on-top.ts`: `startFullScreen(signal?)` starts it out of full screen (again when the signal aborts), `switchFullScreen()` asks the app and keeps its answer unless the page started again meanwhile, and `isFullScreen()` gives it. It never rejects: a failed switch shows why and leaves the state. Every answer that the window is full screen shows the Notice "Press F11 or Esc to leave full screen": the app switches rather than sets, so each such answer is one going in, even when the page expected otherwise; leaving shows none. `main.ts` starts it after Keep on top.
- **The command** `fullScreen` in `page/src/commands.ts`: "Full screen", F11 alone, `pressed: isFullScreen`, running `switchFullScreen().then(refreshCommands)`; in the right-click menu after Keep on top, with a check mark; no title bar button; always available. F11 with Ctrl, Alt, Shift, the Windows key or AltGr (Ctrl+Alt) isn't the shortcut, by the table's exact-modifier match.
- **Contract:** the answer's sample is `app/tests/fixtures/full_screen.json` (`switchedOn`, `switchedOff`), written by `full_screen::contract_samples` beside Keep on top's; `switch_full_screen` joins the commands the tests' fake app must be told how to answer. `npm run fixtures` added only that file.
- **Tests** (written first, failing): `page/src/full-screen.test.ts`: `F11 and the menu entry each ask the app to switch full screen`; `the menu entry names Full screen and its key, after Keep on top`; `F11 with Ctrl / Alt / Shift / the Windows key / AltGr switches nothing`; `a new window starts out of full screen: its menu entry isn't ticked`; `the menu entry is ticked once the app answers that the window is full screen, and not once it answers that it left`; `the menu entry shows the state the app answers with, not the one the page expected`; `full screen isn't a setting: a settings change from any window leaves it as the app answered`; `a switch the app answers after the window's page started again leaves the window out of full screen and shows no Notice`; `a full screen the app couldn't switch says why, and the menu entry stays as it was`; `each time the window goes full screen a Notice says how to leave, and leaving shows none`; `F11 switches full screen in a window that shows no document`. `contract.test.ts`: `the app's answers to switch full screen tick its menu entry, with the Notice on how to leave, and untick it`. Changed: `commands.test.ts`'s right-click menu test lists every entry, and Full screen is now one of them after Keep on top. No `cargo test` for the command: it is two calls to a real window, as for Keep on top.
- **Not done:** the hand check in the release build. The title bar still shows in full screen (ticket 03), Esc doesn't leave it (ticket 02), and the maximize button is unchanged (ticket 05).
