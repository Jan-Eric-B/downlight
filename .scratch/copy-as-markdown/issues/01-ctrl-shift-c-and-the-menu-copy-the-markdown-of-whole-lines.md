# 01: Ctrl+Shift+C and the menu copy the Markdown of whole lines

**What to build:** The reader presses Ctrl+Shift+C, or picks "Copy as Markdown" in the right-click menu, and the clipboard gets the document's Markdown instead of the text they see (**Copy as Markdown**). A selection copies the file's whole lines, from the first block it touches to the last, dropping only the whitespace every copied line starts with, so a nested list pastes as a list. With nothing selected, it copies the whole file. It copies the file as the shown render was made from it: a **Sort** or a **Tick** never changes it, and a file changed or deleted since keeps copying what is shown. It is unavailable while the window shows no document. A code block or a table the selection touches copies its whole lines for now; tickets 02 and 03 copy only the selected part.

Spec: [Copy as Markdown, and a clean rich copy](../spec.md)

**Blocked by:** None (can start immediately)

**Status:** built, hand checks left

- [x] The core gains a copy module with one public function: given the bytes a render took and the pieces of the file (ranges of whole lines, 1-based; no pieces for the whole file), it returns the Markdown. It decodes the bytes as render does, drops the whitespace every non-blank copied line starts with (keeping `> ` and list markers), and joins the lines with `\n`. A piece outside the file is its error type, one for the feature.
- [x] Reading and rendering returns the file's bytes with the rendered document, shared rather than copied. The document table keeps, for each window, the bytes of the render its page took last with that render's showing. It replaces them when the page takes a reload's or another document's render, and drops them when the window shows no document or closes.
- [x] A new app command, `copy_markdown`, takes the showing the view shows and the pieces, and answers as `open_document` does (nothing, or a Notice). It runs on a background task. A showing other than the kept one copies nothing and sends nothing. The page never receives the Markdown.
- [x] The Windows module writes Unicode text to the clipboard through Win32 (`windows-sys` with the clipboard and global memory features; paste-markdown/01 adds the same for reading, so whichever is built first adds them). It writes line breaks as `\r\n` and answers busy after a few short retries while another program holds the clipboard. Other systems' fallback answers that Copy as Markdown isn't available yet. The `unsafe` code stays in the Windows module.

- [x] A new page module maps the selection to pieces from the line numbers the rendered blocks carry: the lines from the start of the innermost block containing the selection's start to the end of the one containing its end. ## Results

Built on 2026-11-25.

- **Core.** `core/src/copy.rs`: `markdown_of(bytes, pieces)` with `Piece::Lines { first, last }` and `CopyError::NotInTheFile(piece)`. It decodes as render does and splits lines as comrak does (`\n`, `\r\n` and a lone `\r`), so the lines are the render's. The shared indentation is the longest run of spaces and tabs every non-blank copied line starts with, taken over all pieces together; a blank line, also one of only spaces, copies as an empty one. No pieces copy the whole file as it is written, indentation and all (a file indented throughout keeps it). The copy ends without a line break. `Piece` is an enum so that tickets 02 and 03 add their kinds (a span within a line, say) beside `Lines`, and `CopyError` gains their errors.
- **The kept bytes.** `app/src/render.rs` returns `Rendered { document, bytes, stages }`, the bytes as `FileBytes = Arc<Vec<u8>>` (no second copy, which `Arc<[u8]>` would make). `app/src/documents/shown_bytes.rs` keeps two slots on each window's record: the bytes of the render the page placed (`placed`) and those of its latest request's render (`answered`), each with its showing. Each request (`handover`) gets a number and empties `answered`; `Documents::rendered`, which `render_document` now awaits the render through, keeps the bytes only for the latest request, so an overtaken render never lands. `arrived` moves `answered` to `placed` when its showing matches; an answer for another showing without bytes (a show or return that can't be read) empties `placed`, and a reload that can't be read keeps it, as the page keeps its render. Stop empties `answered` and retires the latest request under the table's lock, so a render that finishes after the Stop (the core's sanitizing runs to its end once started, and Stop leaves the render only after the lock) keeps nothing either: a stopped 100 MB document is not held until the page next asks (review fix). The empty window (a handover with no document) empties both, and closing the window drops the record. So a copy while a reload or another document is on its way, after Stop, and after the file changed or was deleted copies what the view shows.
- **App.** `app/src/copy.rs`: the command `copy_markdown(showing, pieces)` (a blocking task), `copy(documents, window, showing, pieces, write)` with the clipboard writer passed in, `ClipboardError` and `CopyError`, turned into the spec's Notices (plus "Can't copy the Markdown: ..." when Windows refuses the text, and "Copying the Markdown failed: ..." for a failed task). A showing other than the one kept writes nothing and answers nothing.
- **Clipboard.** `platform::write_clipboard_text(window, text)` in `app/src/platform/windows/clipboard.rs`: the text with `\r\n` line breaks and a NUL as UTF-16 in new `GMEM_MOVEABLE` memory (`OwnedGlobal::holding_clipboard_text`, made before the clipboard is opened: the units are counted first, the memory allocated once and the text encoded straight into it, and a U+0000 in the text is written as U+FFFD, since a NUL would end `CF_UNICODETEXT` early), then `OpenClipboard` with the window's HWND (tried 10 times 25 ms apart, as Paste does, before it answers busy), `EmptyClipboard` and `SetClipboardData(CF_UNICODETEXT)`. The clipboard is opened for the window rather than for no window, since Microsoft documents that `EmptyClipboard` then gives the clipboard no owner and `SetClipboardData` fails. On success the clipboard owns the memory (`into_handle`); memory it refused is freed by the guard. Reading and writing share the open-with-retries guard. No new windows-sys features: Paste had added them. Other systems' fallback answers `NotAvailable`.
- **Page.** `page/src/copy-as-markdown.ts` (`copyAsMarkdown`, `canCopyAsMarkdown`) takes the selection as far as it lies in the document view (`selectionInView` in `view.ts`). A selection touches a block by holding one of its characters, wherever its ends are (reworked after review): the page walks the selection's text nodes, skipping whitespace outside `pre` and the page's own parts (copy buttons, heading anchors), so a triple-click, which Chromium ends at offset 0 of the next block, and a drag that starts at the end of the block before, don't touch that block. The piece runs from the first line to the last of the blocks touched (each character's innermost `[data-sourcepos]`, a cell's table), since footnotes render at the end but keep their definitions' lines; a touched block's nested blocks the selection doesn't reach are left out, so a list item's text copies without its nested list. No selection, a collapsed one, one outside the view, one touching no character and one holding the whole view (Ctrl+A) send no pieces, and so does one only in raw HTML, which has no line numbers. `page/src/sourcepos.ts` reads `data-sourcepos` for the whole page: a block ending at column 0 (comrak's last list item) ends on the line before, and a malformed one gives no lines. The commands table gains `copyAsMarkdown` (Ctrl+Shift+C, `leavesEditableFields`, available while the view shows a render, so also not while the view shows why a document can't be read), in the menu directly after Copy.
- **Contract.** `copy_markdown` is typed in `page/src/app.ts` with `Piece`; `app/tests/fixtures/copy_markdown.json` samples a line range and the whole file (`copy::contract_samples`), and `contract-copy-markdown.test.ts` checks the pieces the page sends against them.
- **Performance.** Ctrl+A short-circuits to the whole file without walking the view. A large partial selection walks its text nodes once, from where it starts and reading no layout, then each touched block once more for its code lines, rows or nested blocks, so the work grows with the selection, not the document.
- **Tests.** `core/tests/copy.rs` (14), `app/src/documents/tests/copy.rs` (12, the clipboard replaced by a recorder; also a reload that can't be read, a document on its way, Stop, and a piece outside the file), `page/src/copy-as-markdown.test.ts` (18; after review, 25 in its first group, adding triple-clicks ending at the next block or its text, a start at the end of the block before, whitespace only, a nested list item, footnotes both ways, a selection past the view's end, a malformed `data-sourcepos`), and in `commands.test.ts` and `contract.test.ts`. The menu test that lists every entry was changed to add Copy as Markdown, since the menu now has it.
- **Noteworthy.** A selection that holds the whole view copies the whole file rather than the lines from its first block to its last, so Ctrl+A keeps link reference definitions and blank lines at the end of the file. In this checkout, `npm run check`'s Prettier step also reads another agent's worktree under `.claude/worktrees/` (ignored only through `.git/info/exclude`, which Prettier doesn't read) and fails on its fixtures; every step passes on the repository's own files.
- **Measuring (left for the owner).** With `DOWNLIGHT_TIMING` set, each copy that writes the clipboard prints `timing <window> copy-markdown at=... markdown=... clipboard=...`: `markdown` is looking up the kept bytes and the core's `markdown_of`, `clipboard` is opening and writing the clipboard. Open `target/documents/mixed-1mb.md` (`npm run documents`) in the release build with the switch, press Ctrl+A and then Ctrl+Shift+C 5 times, and take the medians.
- **Review fixes (Rust side).** The app's own `Piece` is gone: `downlight_core::Piece` derives serde with the tag `piece` and camelCase kinds, so `copy_markdown.json` is byte-identical. The kept bytes' fields are `placed` and `answered`, with the latest request kept as `Option<Request>` that Stop and the empty window retire; `shown_bytes.rs` says why the number exists beside the render's leaver. `Rendered`'s `Debug` prints sizes, not the file. Tests added in `app/src/documents/tests/copy.rs`: a render that finishes after a Stop keeps no bytes, an overtaken render's bytes never land (checked by pointer), Back and Forward copy the document each step returned to, a show that can't be read lets go of the bytes before it, and a window put back to no document lets go of its page's bytes once the page asks again. The Stop test now asserts the stopped render's bytes are gone through `Arc::downgrade`. The `arrive` test helper, which skipped `rendered()`, is replaced by `take`, which follows production, and `page_asks` follows it too.
