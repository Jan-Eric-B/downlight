# 02: Copy as Markdown of part of a code block

**What to build:** **Copy as Markdown** of a selection within one code block copies exactly the selected text, as Ctrl+C does. A selection that runs into or out of a code block copies the code lines it touches, inside the block's own fences with its language, so the paste is valid Markdown holding only the code the reader chose. Front matter counts as a fenced block: its `---` lines are its fences. The copy button keeps copying the whole block's code.

Spec: [Copy as Markdown, and a clean rich copy](../spec.md)

**Blocked by:** 01 (Ctrl+Shift+C and the menu copy the Markdown of whole lines)

**Status:** built, hand checks left

- [x] A selection that starts and ends inside the same code block is not sent to the app: the page writes the selected text to the clipboard itself, as the copy buttons do, and shows a Notice if that fails.
- [x] A code block the selection covers only partly becomes its own pieces: its opening fence line, the code lines touched, and its closing fence line. The code line comes from counting the code's lines before the selection's point. A fenced block is told from an indented one, which has no fences, by comparing the block's lines with its code's lines. An unclosed fence at the end of the document has only its opening line.
- [x] A selection from a paragraph into a code block copies the paragraph's lines through the touched code lines, then the closing fence. A selection from a code block into the text after it copies the opening fence, the touched code lines through the block's end, then the text's lines.
- [x] Core tests: code lines between their fences, from pieces the page would send for a fenced block, a fenced block inside a list item (its shared indentation dropped), front matter, and an indented code block.
- [x] Page tests (rendered fixtures): a selection within one code block writes its text without asking the app; the pieces sent for a selection into a code block, out of one, and into front matter; an indented code block sends no fence lines.
- [ ] Hand checks in the release build: Copy as Markdown pasted into VS Code and a GitHub comment from within a code block, into one, out of one, and into front matter.
- [x] `npm run check` passes.

## Results

Built on 2026-11-25.

- **Core.** No new code: a code block's parts are ranges of whole lines (its opening fence line, the code lines touched, its closing fence line), so `Piece::Lines` and `markdown_of` already copy them, with the shared indentation dropped for a fenced block in a list item. Only `Piece`'s doc comment changed. `core/tests/copy.rs` gained 6 tests (20 in all) from pieces the page would send, with line numbers from the core's own render: a fenced block's touched lines between its fences, a paragraph through touched code lines then the closing fence, a fenced block in a list item, front matter, an indented block (no fences) and an unclosed fence (opening line only). They passed as soon as they were written, since the core's design already held them.
- **Page.** New `page/src/copy-code-block.ts`: `codeHolding` (a code block's code, by the one `CODE_SELECTOR`), `selectedCode` (the selection's text within it) and `codeLinesLeftOut(block, selected)`, which names the code lines of a touched block that hold no selected character (reworked after review, with the same interface as a table's `rowsLeftOut`: wherever the copy starts or ends, and a code block between two others is no longer special). A block's lines are read by counting its code's lines (`code.textContent`) against its `data-sourcepos` lines: equal is an indented block (all lines are code), one more is an unclosed fence, two or more is a fenced block, front matter included (its trailing blank lines are dropped from the YAML, so it can have more). Anything with fewer lines than code is copied whole. A line break is part of the line it ends, so a selection ending right after one doesn't touch the next line, and one starting at the end of a line, before its line break, or after the block's last line break, doesn't touch that line or the block. In `copy-as-markdown.ts`, ticket 01's first-to-last lines lose each touched code block's untouched code lines (`linesWithout`), so a selection into a code block ends with its closing fence, and one out of it starts with its opening fence. When every character the selection holds is in one code block's code, `copyAsMarkdown` writes that text to the clipboard itself, with no `copy_markdown` call, also when the selection runs on beside the copy button, out of the view or around the block. `page/src/copy.ts` gained `copyCode(text)`, which the copy buttons now use too: it writes the text and shows "Can't copy the code: ..." if that fails, so the Notice of a failed selection copy is the buttons' own. The copy buttons still copy the whole block's code.
- **Fixture.** `core/tests/fixtures/code-in-text.md` and its HTML (written by `npm run fixtures`; no existing fixture changed): a fenced block in a list item, an indented block with a blank line, and an unclosed fence at the end.
- **Tests.** 13 new page tests in `copy-as-markdown.test.ts` (within one code block, within front matter, a failing clipboard, and the pieces sent for a selection into a block, out of one, between two, over one whole, out of and into front matter, in a list item, into and out of an indented block, and both unclosed-fence cases). One test changed: "of a whole code block, for a selection inside it" (ticket 01, which copied the whole block for now) is gone, since a selection inside one code block now copies its text and the new tests cover it. After review, two more changed, since every character they select is in one code block and the page now writes it: a selection running into the front matter from before the view, and one running out of the view from an unclosed fence. New tests: a selection ending at the start of a block's code or its wrapper, starting after its last line break or before it, ending in an element around the block or beside its copy button, made backward, and over a code block and a table.
- **Contract.** No change: the pieces are the same shape, so the app's samples are unchanged.
- **Left.** The hand checks.
