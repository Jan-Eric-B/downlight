# 11: A missing file's notice opens its folder

**What to build:** A notice that names a file shows the file's name in bold and its folder as a link apart from the rest of the text, and when the file is missing but its folder is there, a click on the folder opens it in Explorer. For example: "Can't find **delete-me.md** in [C:\Users\me\docs](#)."

Spec: [Window design](../spec.md)

**Blocked by:** 04 (The logo and the file name in the title bar)

**Status:** ready-for-human

- [x] Every notice that names a file shows its name in bold and its folder after it, instead of the whole path as plain text. This covers at least following a link to a missing document (`FollowError::NotFound` in `app/src/links.rs`) and clicking the title bar's file name when the file is gone (`RevealError::NotFound` in `app/src/title_bar.rs`); find the other errors and notices that name a path (open, drop, launch, reload) and give them the same shape.
- [x] When the file is missing and its folder exists, the folder is a link in the link role's color (`--accent-link`), and a click opens the folder in Explorer. When the folder is gone too, it is plain text and nothing is clickable.
- [x] A notice with a link stays while the pointer is on it or it has the focus, and goes its usual few seconds after that. The link is reachable with Tab and has an accessible name.
- [x] A long path breaks only at its backslashes, never inside a name (today "delete-me.md" breaks after "delete-").
- [x] The page never sends the app a path of its own choosing to open: the folder to open is one the app named in the notice, and the app checks it (an existing folder) before opening it. Opening uses the same platform call as a link's "open a folder" action.
- [x] The notice's shape is typed in `page/src/app.ts`, with contract samples (`npm run fixtures`) for the message and for the errors that carry a file.
- [x] Page tests: the name is bold and the folder a link when the folder exists, plain when it doesn't; a click on the folder sends the request; the notice stays while hovered or focused.
- [x] App tests: each missing-file error carries the name, the folder and whether the folder exists; the open-folder command refuses anything that isn't an existing folder.
- [ ] Checked by hand: follow a link to a deleted document, and click the title bar's name after deleting the shown file; each time the notice's folder opens Explorer there. With the folder deleted too, the folder is plain text.

## Comments

**2026-11-16, from ticket 04's hand check.** The reader asked for a way to open the folder of a missing file and for the path to stand apart from the rest of a notice. Decided with them:

- The folder is a link inside the notice, not a button, and the notice doesn't take a click anywhere else: a notice vanishes after a few seconds, so it holds at most one small action, and it stays while that action is in reach.
- No "Create" for a missing file. Downlight is reading-only (glossary: changing a file happens in another program), and a created empty file would show an empty window; creating files is the Editor's job.
- The look: the file name in bold, the folder as a link, e.g. "Can't find **delete-me.md** in C:\\...\\handcheck."

**2026-11-16, built; the hand checks are left.** What was built, and what it decided:

- **One shape for what the reader is told.** `Notice` in the new `app/src/notice.rs` is plain text or `{ before, file, after }`, where the file is a `NamedFile`: `{ name, folder, folderOpens }`, with `folder` null for a path with none (a drive's root). Every error that reaches the page (`FollowError`, `RevealError`, `OpenError`, `DocumentError` and the new `OpenFolderError`) builds its notice in one `notice()` method, and serializes and displays through it, so the plain text the app's tests and logs see reads as the page shows it: "Can't find a.md in C:\docs." `Message::Notice` carries a `Notice` too. The page types it in `page/src/app.ts` (`Notice`, `NamedFile`); every command rejects with one, and a string is still a notice, so `tauri::Error`s need nothing.
- **What names a file now:** a link's missing, unreachable, unrevealed or unshown file and its folder that didn't open; the title bar's reveal; Open's and a drop's document that can't be shown; a document that can't be read, in the view on a show and as a notice on a reload (the reload case of the ticket); and the watch that can't start. A launch's failures stay plain text: they go to Windows' message box, which holds no link, and a launched file that is missing opens its window and says why in the view, with the new shape. Two texts changed with the shape: a failed reveal is "Can't show **a.md** in C:\docs in Explorer: ..." (it said "in its folder", which reads oddly after the folder), and a folder is "**docs** in C:\ is a folder, not a document". "Explorer" is Windows' word in OS-neutral code; v1 is Windows only, and a port that reveals files revisits it. A share's root shows as `\\server\share\`, as Windows writes it.
- **Only a missing file's folder opens**, and only when it is there: `NamedFile::missing` looks at the folder where the error is made, on the blocking thread that found the file missing, never while the error is sent; `NamedFile::at`, for every other error, never opens. A file that is there needs no folder link: the reveal shows it.
- **The page can't have a folder of its own choosing opened.** `NamedFile::missing` remembers each folder it offers, by the text the page gets, in a process-wide map, and the new command `open_named_folder { folder }` opens only a folder in that map, and only if it is a folder now: a folder gone since, or a file put in its place, fails as "Can't find ...", and one whose state can't be told (an offline share) as "Can't reach ...". It opens with `platform::open_folder`, the call behind a link's "open a folder", on a blocking thread. The map is a `static` in `notice.rs` rather than the app's managed state, since the errors that name folders are made on background threads that hold no app handle (the render module knows nothing of windows); it grows by one entry for each missing file the reader is told of, which stays small, so it is never pruned.
- **The page builds a notice in one place**, `noticeContent` in `page/src/notice.ts`, which the notices and the view's "can't read" both use. The name is a `strong`; the folder follows " in ". A folder that opens is a `span` with `role="link"`, `tabindex="0"` and the accessible name "Open the folder C:\...", which a click or Enter opens: not an `a`, so `links.ts` never follows it inside the view's article, and not a `button`, which is laid out as one box and wouldn't wrap with the text. A mouse press on it doesn't take the focus, so the notice doesn't stay after the click until the reader clicks elsewhere; Tab still reaches it. It takes the link role's color (`--accent-link`, `LinkText` in high contrast), underlines on hover and has the emphasis role's focus ring; `accent.test.ts`'s table has both rows.
- **Holding the notice:** while the pointer is on a notice that has a folder link, or the focus is in it, it doesn't go; 4 s after the pointer leaves or the focus goes, it does. A notice without a link goes as before, pointer or not.
- **Breaking:** the name and each part of the folder up to and with its separator are `white-space: nowrap` (`.unbreakable`), with a `wbr` between the parts, so a path breaks only after a backslash. A single name wider than the notice (640 px) runs past its edge rather than breaking.
- **Contract samples** (`npm run fixtures`, diff reviewed): `follow_link.json` has `notFound` and `notFoundInGoneFolder`, `title_bar.json` has `revealNotFound`, `render_document.json`'s unread answers carry the shape, and `messages.json` has `noticeNamingFile`. The page's contract tests show each, check the bold name and the folder link or its absence, and that a click sends the sampled folder back. The tests' fake app fails a command with a notice through `failingWith` in `test-support.ts`, as Tauri does, not with an `Error`.
- **No new glossary term:** `NamedFile` is the file a Notice names, the glossary's Notice and Document.

**Hand checks** (on the release build, `npm run tauri build`), to record here:

1. Follow a link to a document that was deleted: the notice reads "Can't find **name.md** in C:\...\folder." with the folder in the link color, underlined on hover; a click opens Explorer at that folder. The notice stays while the pointer is on it and goes about 4 s after it leaves.
2. Delete the shown document's file and click the title bar's name: the same notice, ending "so it can't be shown in its folder.", and its folder opens Explorer there.
3. Delete the folder too and repeat 1 and 2: the folder is plain text, the pointer shows no hand, and the notice goes after 4 s with the pointer on it.
4. With a notice whose folder opens, press Tab until the folder has the focus ring: the notice stays while it has the focus, Enter opens Explorer, and Narrator reads "Open the folder C:\...". Moving the focus away, the notice goes about 4 s later.
5. A long path in a narrow window (a missing `delete-me.md` a few folders deep): the folder wraps only after a backslash, and "delete-me.md" never breaks after its hyphen.
6. Launch `downlight` on a file that doesn't exist, in a folder that does: the window says "Can't read **name.md** in C:\...: ..." and the folder opens Explorer.
7. Light, dark and a contrast theme: the name and the folder link are legible, and the focus ring shows.

**2026-11-16, from the review.** Five findings, all taken; the JSON the page gets is unchanged.

- **One way from an error to a notice.** `FollowError`, `RevealError`, `OpenError`, `DocumentError` and `OpenFolderError` lost their `notice()`, `Display` and `Serialize`; each has one `From<...> for Notice` instead. The commands reject with a `Notice` (`Result<T, Notice>`), and `render_document`'s answer carries one for a read that failed. The tests read `Notice::from(error)`. `ShowError` keeps its `Display` and takes no other path: it is never sent alone, only after a document's name, in a notice or in a launch's failure for Windows' message box.
- **Offering a folder has a name.** The process-wide map is a `NamedFolders` with `offer(folder) -> bool`, the one way a folder becomes one the page may have opened, and `open(folder)`, which opens only an offered folder that is a folder now, with `platform::open_folder`. `NamedFile::missing` sets `folderOpens` from what `offer` returned, so the two can't disagree; the one instance is still a `static`. The notice tests each make their own `NamedFolders`, so they use the crate's own folder where it only has to be there; a temp folder is left only to the two tests that delete it. `NamedFile::sample` is offered nowhere: the samples are only shapes, and the page's tests answer `open_named_folder` with their fake app.
- **`Notice::reveal_failed`** in `notice.rs` builds the whole failed reveal's notice, for a link's reveal and the title bar's.
- **The page checks a rejection's shape.** `isNotice` in `page/src/app.ts` checks `before`, `file` (`name`, `folder`, `folderOpens`) and `after`, and `showingWhy` uses it; anything else shows as text. `notice.test.ts` fails `open_named_folder` with a notice through `failingWith` and checks the bold name; a new test keeps the case of Tauri's own `Error`, shown as text.
- **Contract sample:** the new `open_named_folder.json` holds `notFound` (`npm run fixtures`, no other sample changed), and `contract.test.ts` shows it after a click on a notice's folder, with its name in bold.
