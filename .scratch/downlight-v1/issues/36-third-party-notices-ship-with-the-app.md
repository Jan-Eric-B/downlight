# 36: Third-party notices ship with the app

**What to build:** Every license notice the app's dependencies require in a binary distribution ships with Downlight, and so does Downlight's own `LICENSE` (GPL-3.0). Today only the page's notices ship (`licenses.md` from Vite's `build.license`, and `grammar-licenses.md` from ticket 17), embedded in the exe where no reader can see them; the Rust crates' MIT and Apache-2.0 notices (Tauri, comrak, ammonia, two-face and the rest, 274 packages for `x86_64-pc-windows-msvc`) and Downlight's `LICENSE` ship nowhere, though MIT and Apache-2.0 ask for their notices in every copy.

Downlight ships only as the per-user NSIS installer (spec: Platforms), so every copy gets the files the installer writes. The notices go there as readable files next to `downlight.exe`, and leave the exe.

Spec: [Downlight v1](../spec.md)

**Blocked by:** 17 (Installer and file associations)

**Status:** ready-for-human

- [x] The notices of every Rust crate in the release build are generated from `Cargo.lock` by cargo-about, for the same target as `deny.toml` (`x86_64-pc-windows-msvc`) and accepting only the licenses `deny.toml` allows, not written by hand. The workspace's own crates are left out, as in cargo-deny.
- [x] One third-party notices file holds them all: the Rust crates, the page's packages (what Vite's `build.license` writes today, and Fluent UI System Icons, which ships no license file of its own) and the syntax grammars (two-face's listing). It is committed, so its diff is reviewed.
- [x] The installer puts that file and Downlight's `LICENSE` (as `LICENSE.txt`) in the install folder next to `downlight.exe`, and the uninstaller removes them.
- [x] The notices no longer ship inside the exe: `licenses.md` and `grammar-licenses.md` leave `page/dist/`. The Fluent icons banner at the top of the page's bundle stays, since it is the notice inside the code it covers.
- [x] No test of one part writes into another part's folder: `core/tests/grammar_licenses.rs` stops writing `page/public/grammar-licenses.md`. The core keeps checking that every grammar license is compatible with GPL-3.0; whatever assembles the notices file lives with the app, which owns the installer.
- [x] The check command fails when the committed notices file no longer matches what cargo-about, Vite and two-face give for the current lockfiles, naming `npm run fixtures` as the fix.
- [x] `npm run fixtures` writes the notices file again after a dependency changes.
- [x] CI installs cargo-about (`cargo install --locked cargo-about`, as it does cargo-deny), and CLAUDE.md's Commands name it with the check command's other tools.
- [ ] Hand check: after installing, the install folder holds `LICENSE.txt` and the notices file, both open as text, and uninstalling removes them.

**2026-11-17, triage, decided by the repo owner.**

- **cargo-about is added.** cargo-deny lists license IDs but can't write license texts, and a hand-written reader of `~/.cargo/registry` would be more code to keep. cargo-about comes from Embark, who also make cargo-deny, and is under MIT or Apache-2.0.
- **Installed files, not embedded.** Downlight has no portable build, so the installer reaches every copy, and a file in the install folder is one the reader can open. Nothing in the app shows the embedded notices today, and the exe gets about 190 KB smaller without them. If a portable build comes later, it ships the same two files beside the exe.
- Left to the implementer: the file's name and format (one Markdown or text file), how the installer gets it (Tauri's bundle resources or `app/installer/hooks.nsh`; check Tauri's current docs), and how Vite's license output and two-face's listing are combined with cargo-about's.

**2026-11-19, built.** `npm run check` passes. `npm run tauri build` writes the installer (2.84 MiB, from 2.77 MiB in ticket 17); it hasn't been run.

- **The file:** `app/notices/THIRD-PARTY-NOTICES.txt`, plain text (438 KB, 11,900 lines), committed. Plain text rather than Markdown: it opens with a double-click wherever Downlight isn't the Markdown default, and no license text can be misread as Markdown (Vite's own Markdown puts license texts in unfenced, so their indentation turned into code blocks). It names `LICENSE` and GPL-3.0 at the top, lists the three parts with their counts, then holds them in order, each license after a rule: 1. the Rust crates, one entry per distinct license text with the crates under it (257 crates, 128 texts); 2. the page's packages, name, version and license (3); 3. the syntax grammars, by their path in bat's tree (66).
- **The installer:** Tauri's bundle resources (`bundle.resources` in `app/tauri.conf.json`), as a map: `../LICENSE` to `LICENSE` and `notices/THIRD-PARTY-NOTICES.txt` to `THIRD-PARTY-NOTICES.txt`, so both land in the install folder beside `downlight.exe`. The generated `target/release/nsis/x64/installer.nsi` shows `File /a "/oname=LICENSE" ...` and `File /a "/oname=THIRD-PARTY-NOTICES.txt" ...` right after the exe's `File`, and the uninstall section's "Delete resources" deletes both before `RMDir "$INSTDIR"`, whatever `$UpdateMode` is (an update writes them again). No change to `app/installer/hooks.nsh` was needed. tauri-build also copies them beside the debug and release exe in `target/`.
- **Assembling:** `scripts/notices.js` (`npm run check:notices` checks, `--write` writes; `npm run fixtures` now ends with it) takes:
  - the Rust crates from `cargo about generate --locked --fail --manifest-path app/Cargo.toml --format json`, configured by `app/notices/about.toml`: `deny.toml`'s target and licenses, the workspace's own crates ignored, dev-dependencies left out (only tests use them), build dependencies and proc macros kept (a superset is safe). The accepted list is in order of preference, MIT first, so a crate under "MIT OR Apache-2.0" gives its MIT text, which is short and carries the authors' copyright (the file went from 629 KB with alphabetical order to 438 KB). `--fail` fails on a crate whose license can't be told. It has to run online (`cargo metadata` downloads the crates of other targets), as cargo-deny does.
  - the page's packages from Vite's JS `build()` with the project's config, `write: false` and `build.license: { fileName: "licenses.json" }`, so the check builds the page in memory and writes nothing to `page/dist/`. Vite gives no text for `@fluentui/svg-icons`; its license now lives in `page/fluent-icons-license.txt`, from which `vite.config.ts` builds the bundle's banner (byte for byte the same banner as before) and the script fills the notice. Any other package without a license text fails the script, naming it.
  - the syntax grammars from `cargo run --example grammar_licenses -p downlight`: `app/notices/grammar_licenses.rs` prints two-face's `for_syntaxes()` listing as JSON. two-face is now an app dev-dependency at the core's version and features, so it added nothing to the tree. An example, so it never ships.
- **Out of the exe:** `vite.config.ts` sets `build.license: false`, so `page/dist/` holds only `index.html` and `assets/`; `page/public/grammar-licenses.md` (and the then-empty `page/public/`) is deleted. The release exe has neither notice text in it any more; the Fluent banner is still there.
